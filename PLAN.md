# Хексленд — план проекта

Браузерная настольная игра про ресурсы, торговлю и строительство на карте из шестиугольников.
Механика как в классических играх этого жанра, но название, арт и оформление свои.
Подключение как в Kahoot: на большом экране PIN и QR-код, игроки заходят с телефонов или ноутбуков.

> **Если вернулись после перерыва:** смотри раздел «Статус» в самом конце, там отмечено, что сделано и что дальше.

---

## 1. Что договорились

| Тема | Решение |
|---|---|
| Название | **Хексленд** |
| Платформа | Браузер. Одна страница игрока работает и на телефоне, и на ПК (адаптивная вёрстка) |
| Сеть | **Firebase** (как в нашем кахуте): Realtime Database + анонимный вход + Hosting. Своего сервера нет, играть можно онлайн откуда угодно. Нужен интернет |
| Игроки | от 3 до 6 человек + отдельный экран хоста (ноут, выведенный на телевизор) |
| Вход | PIN-код комнаты или QR-код на экране хоста |
| Карта | Каждую игру случайная. 3–4 игрока: 19 гексов, 5–6 игроков: 30 гексов |
| Правила | Классические + состав расширения на 5–6 игроков. Ход при 5–6 обычный, без особых правил (см. 3.11) |
| Язык | Русский |
| Арт | Сначала заглушки (цветные гексы, иконки). Потом подставляем свои картинки, сгенерированные в ChatGPT |
| Переподключение | Автоматическое, без повторного ввода PIN (даже после закрытия вкладки). Ожидание 2 минуты (можно поменять в лобби), потом решает хост |
| «Мозг» игры | Страница хоста (ноут у телевизора): считает правила и пишет состояние в Firebase |

**Граница по «клону»:** механику повторяем, правила пишем своими словами. Чужое название, логотипы, арт и текст официальных правил не используем.

## 2. Архитектура

Основа — подход из нашего кахута (`Desktop\кахут`): Firebase вместо своего сервера.

```
                       Firebase (облако)
          ┌──────────────────────────────────────────┐
          │ Realtime Database  +  Анонимный вход     │
          │ Hosting: https://<проект>.web.app        │
          └───────▲───────────────────────▲──────────┘
     действия     │  состояние            │ состояние (общее + свои карты)
     игроков      │  (пишет только хост)  │
          ┌───────┴────────┐       ┌──────┴───────────┐
          │  ХОСТ (ноут →  │       │ ИГРОКИ (до 6)    │
          │  телевизор)    │       │ телефон или ПК   │
          │  /host.html    │       │  /  (index.html) │
          │  движок правил │       │  кнопки действий │
          └────────────────┘       └──────────────────┘
```

**Главный принцип: страница хоста — единственный источник правды.**
- Игроки пишут в базу только *намерения* («построить дорогу на ребре X») — каждый в свою папку `actions/<uid>`.
- Хост читает очередь действий, прогоняет через движок правил, записывает новое состояние и удаляет обработанное действие.
- Правила безопасности базы не дают игроку писать ничего, кроме своих действий, своей отметки «в сети» и своей записи в лобби.

**Каждый игрок видит только своё:** общее состояние (карта, постройки, кол-во карт у всех) лежит в `public`, а карты на руке — в `private/<uid>`, который может читать только этот игрок. Колода карт развития лежит в `hostOnly`, её видит только хост.

**Если хост перезагрузил страницу / ноут уснул:** игра встаёт на паузу. Полное состояние хранится в базе (`hostOnly/state`), хост открывает страницу снова и игра продолжается с того же места.

### Что берём из кахута
| Из кахута | Как используем |
|---|---|
| `initFirebase()` в `common.js` (анонимный вход, смещение серверного времени) | Переписываем на TypeScript + модульный Firebase SDK. **Persistence меняем на `LOCAL`** (в кахуте `SESSION`), чтобы игрок возвращался даже после закрытия вкладки. Для тестов `?test=1` → `SESSION`, чтобы в одном браузере открыть несколько игроков |
| Создание комнаты: случайный 6-значный PIN, попытка записать `meta`, при занятом — повтор | Так же |
| QR-код с адресом `…/?pin=XXXXXX` | Так же (библиотека `qrcode`) |
| «В сети / не в сети» через `.info/connected` + `onDisconnect()` | Основа для таймера переподключения |
| Удаление игрока хостом (`kicked/<uid>`) | Так же, в лобби |
| Возврат хоста в игру после перезагрузки (по сохранённому PIN + проверка `meta.hostUid`) | Так же, но храним в `localStorage` |
| `database.rules.json` с проверкой `auth.uid` | Пишем свои правила под новую структуру |
| `firebase deploy` | Так же |

### Стек
- **Язык:** TypeScript
- **Клиент:** Vite + React, две страницы: `index.html` (игрок) и `host.html` (хост). Карта рисуется в SVG
- **Сеть:** Firebase JS SDK (модульный, через npm): Realtime Database + Auth (анонимный)
- **Хостинг:** Firebase Hosting (папка сборки `dist`)
- **Тесты движка:** Vitest
- **QR-код:** библиотека `qrcode`

**Отдельный Firebase-проект для Хексленда** (не тот, что у кахута): у проекта один файл правил базы, и выкладка Хексленда перезаписала бы правила кахута.

## 3. Правила игры (спецификация для движка)

### 3.1 Ресурсы и местность
| Местность | Ресурс |
|---|---|
| Лес | Дерево |
| Холмы | Кирпич |
| Пастбище | Овцы |
| Поле | Пшеница |
| Горы | Руда |
| Пустыня | — (тут стартует разбойник) |

### 3.2 Состав карты
| | 3–4 игрока | 5–6 игроков |
|---|---|---|
| Ряды гексов | 3-4-5-4-3 (19) | 3-4-5-6-5-4-3 (30) |
| Лес / Пастбище / Поле | по 4 | по 6 |
| Холмы / Горы | по 3 | по 5 |
| Пустыня | 1 | 2 |
| Жетоны чисел | 18: 2, 3,3, 4,4, 5,5, 6,6, 8,8, 9,9, 10,10, 11,11, 12 | 28: то же + ещё по одному 2,3,4,5,6,8,9,10,11,12 |
| Гавани | 9: 4× «3:1» + по одной «2:1» на каждый ресурс | 11: + ещё одна «3:1» и одна «2:1 овцы» (✅ сверено) |
| Карт ресурсов в банке | по 19 каждого | по 24 каждого |

**Генерация карты:**
1. Перемешать местность и разложить по гексам.
2. Разложить жетоны чисел на все гексы кроме пустынь.
3. **Ограничение:** красные числа (6 и 8) не должны стоять на соседних гексах. Если стоят, перегенерировать (или переставлять, пока не станет ок).
4. Гавани стоят на фиксированных позициях морской рамки, типы гаваней перемешиваются.
5. Разбойник ставится на пустыню (при двух пустынях на случайную из них).

### 3.3 Фишки игрока
| Фишка | Количество |
|---|---|
| Дороги | 15 |
| Поселения | 5 |
| Города | 4 |

Город ставится на место своего поселения, поселение при этом возвращается в запас.

### 3.4 Стоимость
| Что | Цена |
|---|---|
| Дорога | кирпич + дерево |
| Поселение | кирпич + дерево + овцы + пшеница |
| Город | 3 руды + 2 пшеницы |
| Карта развития | руда + овцы + пшеница |

### 3.5 Карты развития
| Карта | 3–4 игрока | 5–6 игроков | Эффект |
|---|---|---|---|
| Рыцарь | 14 | 20 | Переставить разбойника и украсть 1 карту. Считается в «армию» |
| Победное очко | 5 | 5 | +1 очко (видно только владельцу до конца игры / до победы) |
| Строительство дорог | 2 | 3 | Бесплатно построить 2 дороги |
| Изобилие | 2 | 3 | Взять из банка 2 любых ресурса |
| Монополия | 2 | 3 | Назвать ресурс, все отдают тебе все свои карты этого ресурса |
| **Всего** | 25 | 34 | |

- За ход можно сыграть **не больше одной** карты развития (победные очки не считаются).
- Карту, купленную в этот ход, сыграть нельзя (кроме победного очка).
- Любую карту развития можно сыграть **в любой момент своего хода, в том числе до броска кубиков** (✅ сверено с PDF правил).
- Карта «победное очко» не «играется»: она просто засчитывается. Раскрывается, когда с ней набирается 10 очков.

### 3.6 Особые карты (бонусы)
- **Самая длинная дорога** (+2 очка): у кого непрерывная дорога из 5+ сегментов и она длиннее всех. Чужое поселение или город на вершине разрывает дорогу. При ничьей карта остаётся у текущего владельца. Если дорогу владельца разорвали и он больше не лидер: карта уходит единственному лидеру, а при ничьей между несколькими (или если ни у кого нет 5+) — откладывается, пока кто-то не вырвется вперёд (✅ так и реализовано).
- **Самая большая армия** (+2 очка): у кого сыграно 3+ рыцаря и больше всех. Ничья — остаётся у владельца.

### 3.7 Подготовка (расстановка)
1. Случайный порядок игроков.
2. **Змейкой:** каждый по порядку ставит 1 поселение + 1 дорогу рядом с ним. Потом в обратном порядке ещё 1 поселение + 1 дорогу.
3. За **второе** поселение игрок сразу получает по 1 ресурсу с каждого соседнего гекса (кроме пустыни).
4. **Правило расстояния** работает всегда: поселение нельзя ставить на вершину, соседнюю с другим поселением/городом (между ними должно быть минимум одно ребро).

### 3.8 Ход игрока
1. **(опционально) Сыграть рыцаря** до броска.
2. **Бросок 2 кубиков** (бросает хост, случайность только на стороне хоста).
   - Не 7: каждый гекс с этим числом (без разбойника) приносит ресурс: поселение 1, город 2. Это касается всех игроков.
   - **Нехватка в банке:** если ресурса не хватает, чтобы выдать всем, кому положено, никто его не получает. Исключение: если получатель один, он берёт сколько осталось.
   - **Выпало 7:** см. 3.9.
3. **Торговля** (сколько угодно раз):
   - с игроками: только активный игрок с кем-то из остальных;
   - с банком: 4:1, через свою гавань 3:1 или 2:1 (нужно поселение/город на вершине гавани).
4. **Строительство и покупка** (сколько угодно раз, в любом порядке вперемешку с торговлей).
5. **Конец хода.**

Дорога ставится рядом со своей дорогой/поселением/городом. Через чужое поселение дорогу продолжать нельзя.
Поселение ставится только рядом со своей дорогой (после подготовки) и с учётом правила расстояния.

### 3.9 Разбойник (выпала 7 или сыгран рыцарь)
1. (только при 7) Каждый, у кого **больше 7** карт ресурсов, сбрасывает половину (с округлением вниз). Сбрасывают **все одновременно** на своих телефонах, игра ждёт.
2. Активный игрок переставляет разбойника на **другой** гекс.
3. Крадёт 1 случайную карту у одного из игроков, у которых есть поселение/город рядом с этим гексом и есть карты.
4. Гекс с разбойником не приносит ресурсов.

### 3.10 Победа
Первый, у кого **10 очков в свой ход**, побеждает.
Очки: поселение 1, город 2, карта «победное очко» 1, самая длинная дорога 2, самая большая армия 2.

### 3.11 Ход при 5–6 игроках
✅ **Решено: обычный ход, как при 3–4.** Никаких особых правил (ни «особой фазы строительства», ни «парного хода») — в компании с ними не играли, непривычно.
От 3–4 игроков отличается только состав: большая карта (30 гексов), больше ресурсов в банке, больше карт развития, 11 гаваней (см. 3.2 и 3.5).

> Для справки, если когда-нибудь захотим добавить как опцию в лобби:
> - **Особая фаза строительства** (старое правило): после каждого хода остальные по очереди могут только строить/покупать карты развития из того, что на руке; без торговли и без розыгрыша карт.
> - **Парный ход** (официально с 2021): за ход ходят двое; второй (третий слева от первого) не бросает кубики и не меняется с игроками, но может меняться с банком, строить и сыграть карту развития.

## 4. Модель данных (черновик)

```ts
type Resource = 'brick' | 'wood' | 'sheep' | 'wheat' | 'ore';
type Terrain  = 'hills' | 'forest' | 'pasture' | 'fields' | 'mountains' | 'desert';
type DevCard  = 'knight' | 'victoryPoint' | 'roadBuilding' | 'yearOfPlenty' | 'monopoly';

interface Hex      { id; q; r; terrain: Terrain; number?: number }   // осевые координаты
interface Vertex   { id; hexes: HexId[]; harbor?: HarborType }
interface Edge     { id; vertices: [VertexId, VertexId] }

interface Player {
  id; name; color;
  resources: Record<Resource, number>;
  devCards: { type: DevCard; boughtOnTurn: number }[];
  playedKnights: number;
  piecesLeft: { roads: number; settlements: number; cities: number };  // 15 / 5 / 4
  connected: boolean;
}

interface GameState {
  phase: 'lobby' | 'setup' | 'rollDice' | 'discard' | 'moveRobber' | 'steal'
       | 'main' | 'roadBuilding' | 'finished';
  board: { hexes; vertices; edges; robberHex };
  buildings: Record<VertexId, { owner; type: 'settlement' | 'city' }>;
  roads: Record<EdgeId, PlayerId>;
  players: Player[];
  turnOrder: PlayerId[]; currentPlayer; turnNumber;
  bank: Record<Resource, number>;
  devDeck: DevCard[];
  longestRoad?: PlayerId; largestArmy?: PlayerId;
  dice?: [number, number];
  pendingDiscards?: Record<PlayerId, number>;
  tradeOffer?: TradeOffer;
  log: LogEntry[];
  settings: { reconnectSeconds: number; vpToWin: 10 };
}
```

> Актуальные типы — в `src/engine/state.ts` (этот блок — исходный черновик).

**Движок — чистые функции:** `applyAction(state, playerId, action, rng) → { state } | { error }`. Без сети и без случайности внутри (генератор случайных чисел передаётся снаружи), чтобы удобно тестировать.

`devDeck` и полное состояние хранятся только у хоста (`hostOnly`). Игрокам уходят `toPublicView(state)` и `toPrivateView(state, uid)`.

## 5. Структура базы Firebase

Firebase-проект: **`hexland-540c6`** (база в europe-west1, анонимный вход включён). Настройки — `src/net/config.ts`.

```
rooms/{pin}/                                   pin — 6 цифр
  meta        { hostUid, created, status: 'lobby'|'playing'|'finished', settings }
  host        { online, changedAt }            пишет хост; игроки видят «Ждём ведущего…»
  lobby/{uid} { name, color?, joinedAt }       пишет сам игрок, пока status = 'lobby'
  colors/{color} uid                           кто занял цвет; занять можно только свободный
  presence/{uid} { online, changedAt }         пишет сам игрок; onDisconnect → online=false
  kicked/{uid} true                            пишет хост
  actions/{pushId} { uid, action, at }         пишет игрок (только от своего uid); хост читает и удаляет
  results/{uid} { actionId, ok, error?, at }   пишет хост: ответ на действие (ошибка — по-русски)
  public/{поле} …                              пишет хост по полям (только изменившиеся), читают все
  private/{uid} { resources, devCards, … }     пишет хост, читает только этот игрок
  hostOnly    { state }                        полное состояние, видит только хост
```
Отдельного `events` нет: события лежат в `public/log` с номерами `seq` — по ним делаем анимации.

**Как проходит одно действие:**
1. Игрок: `push(actions, { uid, action: { type: 'buildRoad', edge }, at })`.
2. Хост (подписан на `actions`) берёт действия по очереди → `applyAction(...)`.
3. Успех → одним атомарным `update()` записывает изменившиеся поля `public`, нужные `private/*`, `hostOnly/state`, удаляет действие, пишет `results/<uid>`.
4. Ошибка → только удаляет действие и пишет `results/<uid>` с текстом ошибки.

**Правила безопасности (`database.rules.json`), в общих чертах:**
- всё по умолчанию закрыто;
- хост (`auth.uid == meta.hostUid`) пишет всё в своей комнате;
- игрок пишет только `lobby/<свой uid>` (пока лобби), `colors/*` (занять свободный / отпустить свой), `presence/<свой uid>`, `actions/*` (только со своим uid и только если он участник игры);
- `public`, `meta`, `host`, `lobby`, `colors`, `presence` читают все вошедшие; `private/<uid>` и `results/<uid>` — только этот игрок; `hostOnly` — только хост;
- выгнанный (`kicked`) ничего писать не может.

**Типы действий** (точные — в `src/engine/actions.ts`): `rollDice`, `buildRoad`, `buildSettlement`, `buildCity`, `buyDevCard`, `playKnight`, `playRoadBuilding`, `playYearOfPlenty`, `playMonopoly`, `discard`, `moveRobber`, `steal`, `bankTrade`, `offerTrade`, `respondTrade` (accept / decline / counter с составом), `confirmTrade` (с кем именно), `cancelTrade`, `endTurn`.

**Действия хоста** (кнопки на экране хоста, без очереди): начать игру, выгнать игрока, решение по отвалившемуся игроку (ждать / пропустить ход), закрыть комнату.

## 6. Комнаты, вход и переподключение

- Хост открывает `https://<проект>.web.app/host.html` и создаёт комнату → **PIN из 6 цифр** (как в кахуте).
- На экране хоста: PIN крупно + **QR-код** с адресом `https://<проект>.web.app/?pin=XXXXXX`.
- Игрок: сканирует QR (или открывает сайт и вводит PIN) → вводит имя → выбирает свободный цвет → лобби.
- **Цвета (6):** красный, синий, белый, оранжевый, зелёный, фиолетовый. Если двое схватили один цвет одновременно, хост оставляет того, кто был первым.
- Хост нажимает «Начать», когда игроков 3–6. Можно выгнать игрока, нажав на его имя в лобби.

**Переподключение**
- Анонимный вход Firebase с `LOCAL`-persistence: у телефона постоянный `uid`, он и есть «токен» игрока. PIN тоже сохраняется в `localStorage`.
- Открыл страницу снова → тот же `uid` → автоматически вернулся на своё место с теми же картами.
- Отметка «в сети»: `.info/connected` + `onDisconnect()` → `presence/<uid>/online = false`.
- Отвалился → на телевизоре «*Имя* переподключается… 1:59» (таймер считает хост, по серверному времени).
- Если это его ход → игра на паузе. Если не его → игра идёт, пока не понадобится его действие (сброс на 7, ответ на обмен — тогда обмен для него считается отклонённым).
- Таймер истёк → по настройке комнаты «Если игрок не вернулся»:
  - **«за него играет бот»** (по умолчанию) — хост сам отдаёт место среднему боту. Срок считается с того, что позже: ухода из сети или начала его хода/сброса (заблокировал телефон, пока ходили другие, — бот не включится сразу же, как дойдёт его ход);
  - **«решает ведущий»** — «Ждать дальше», «🤖 Отдать боту» или «Пропустить ход» (при сбросе на 7 — «Сбросить за него»).
- Время ожидания настраивается в меню хоста (по умолчанию 120 сек).

**Выход с ботом вместо себя**
- Телефон: ☰ → «🚪 Выйти из игры» → «Точно выйти?» (Остаться / Выйти) → «Кто доиграет за тебя?» (лёгкий / средний / сложный / отмена).
- Карты, постройки, очки, цвет и имя остаются; на телевизоре у игрока значок уровня бота, в журнале «… выходит из игры — вместо игрока теперь бот (сложный)». Если у ушедшего висело предложение обмена — оно снимается.
- На телефоне экран «Ты вышел из игры» → **«Вернуться в игру»** (забрать место у бота, с того же устройства) или «Выйти на главную».
- Пока за игрока играет бот, его собственные действия хост отклоняет (кроме возвращения).
- Ушли все люди — боты доигрывают партию, ведущий может закрыть комнату.
- Движок: действия `handToBot {level}` / `returnFromBot`, действие хоста `handToBot {player, level, auto}`, у игрока флаг `away`, события `playerLeft` / `playerReturned`.

**Хост перезагрузил страницу:** PIN хоста лежит в `localStorage`; хост проверяет, что `meta.hostUid` совпадает с его `uid`, читает `hostOnly/state` и продолжает. Игроки в это время видят «Ждём ведущего…».

## 7. Экраны

### 7.1 Экран хоста (телевизор, 16:9)
- **Лобби:** название, PIN, QR, список подключившихся с цветами, настройки, кнопка «Начать».
- **Игра:**
  - карта по центру (гексы, числа, гавани, разбойник, постройки цветами игроков);
  - панели игроков по краям: имя, цвет, очки (видимые), кол-во карт ресурсов и развития, рыцари, длина дороги, бонусы, статус связи;
  - чей ход + текущая фаза крупно;
  - анимация кубиков;
  - лог последних действий («Даулет построил поселение», «Арман украл карту у Даулета»);
  - всплывающие события: обмен, монополия, сброс на 7, победа.
- **Финал:** победитель, итоговые очки, кнопка «Новая игра».

### 7.2 Экран игрока (телефон и ПК)
- **Сверху:** чей ход, фаза, мои очки.
- **Карта:** зум и перемещение пальцами. В режиме стройки подсвечиваются **только доступные** места, тап → подтверждение.
- **Мои ресурсы:** 5 карточек с количеством.
- **Мои карты развития:** список, неиграбельные в этот ход серые.
- **Запас фишек:** дороги X/15, поселения X/5, города X/4.
- **Кнопки:** Бросить кубики · Построить (дорога/поселение/город) · Купить карту развития · Обмен · Конец хода.
- **Модальные окна:** сброс на 7, выбор жертвы кражи, предложение обмена от активного игрока, выбор ресурса для монополии/изобилия.
- **Вёрстка:** на телефоне всё в колонку (карта сверху, панель снизу), на ПК карта слева, панель справа.

### 7.3 Обмен между игроками (UX)
1. Активный игрок жмёт «Обмен» → собирает «даю» и «хочу» → «Предложить всем».
2. У остальных всплывает предложение: «Принять» / «Отказаться» / **«Встречное предложение»**.
   - Встречное: игрок меняет «даю/хочу» под себя и отправляет активному игроку.
   - Неактивные игроки не могут меняться между собой, только с активным.
3. Активный игрок видит список: кто согласился на его вариант и кто прислал встречные (с составом). Выбирает одно и подтверждает.
   - Активный может в любой момент изменить своё предложение (старые ответы сбрасываются) или отменить обмен.
4. Хост ещё раз проверяет, что карты у обоих есть, и проводит обмен.
